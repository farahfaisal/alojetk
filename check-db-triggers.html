🔧 إصلاح نهائي: إيقاف التحديث التلقائي

⚠️ المشكلة الحالية:

الطلب يتحول تلقائياً إلى "في الطريق" فور تعيين السائق، حتى لو لم يبدأ الرحلة!

1 أولاً: فحص الوضع الحالي

نفذ هذا الكود لمعرفة ما الموجود:

-- فحص الـ triggers الموجودة
SELECT
    trigger_name,
    event_object_table,
    action_statement
FROM information_schema.triggers
WHERE trigger_name LIKE '%driver%' OR trigger_name LIKE '%shipping%'
ORDER BY trigger_name;
👉 افتح SQL Editor

2 ثانياً: الحل النهائي

انسخ والصق هذا الكود بالكامل:

-- ============================================
-- الحل النهائي: حذف كل التحديثات التلقائية
-- ============================================

-- الخطوة 1: حذف كل الـ triggers المرتبطة بتحديث الحالة تلقائياً
DROP TRIGGER IF EXISTS update_order_with_driver_trigger ON driver_waiting_list;
DROP TRIGGER IF EXISTS assign_driver_to_processing_trigger ON driver_waiting_list;
DROP TRIGGER IF EXISTS update_delivery_status_trigger ON driver_waiting_list;

-- الخطوة 2: حذف كل الدوال المرتبطة بالتحديث التلقائي
DROP FUNCTION IF EXISTS update_delivery_status_with_driver() CASCADE;
DROP FUNCTION IF EXISTS update_order_to_processing_on_driver_assign() CASCADE;
DROP FUNCTION IF EXISTS update_order_status_on_driver_assign() CASCADE;

-- الخطوة 3: التأكد من حذف أي نسخ أخرى
DO $$
DECLARE
    r RECORD;
BEGIN
    -- حذف أي trigger يحتوي على "driver" و "status"
    FOR r IN
        SELECT trigger_name, event_object_table
        FROM information_schema.triggers
        WHERE trigger_name LIKE '%driver%status%'
           OR trigger_name LIKE '%status%driver%'
           OR action_statement LIKE '%status%shipping%'
    LOOP
        EXECUTE format('DROP TRIGGER IF EXISTS %I ON %I CASCADE',
                      r.trigger_name, r.event_object_table);
    END LOOP;
END $$;

-- الخطوة 4: رسالة تأكيد
DO $$
BEGIN
    RAISE NOTICE 'تم حذف جميع التحديثات التلقائية بنجاح ✓';
    RAISE NOTICE 'الآن: تعيين سائق = لا يغير الحالة';
    RAISE NOTICE 'فقط عندما يبدأ السائق الرحلة يدوياً → تتغير الحالة';
END $$;

3 ثالثاً: تأكيد النجاح

بعد تنفيذ الكود أعلاه، نفذ هذا للتأكد:

-- التحقق من أن كل شيء تم حذفه
SELECT
    trigger_name,
    event_object_table
FROM information_schema.triggers
WHERE event_object_table = 'driver_waiting_list';

-- يجب أن ترى فقط trigger واحد: record_delivery_completion_trigger
-- أي trigger آخر يجب حذفه!

✅ النتيجة المتوقعة:

  • ✓ تعيين سائق للطلب → الطلب يبقى كما هو (pending)
  • ✓ السائق يضغط "بدء الرحلة" → الطلب يتحول إلى "في الطريق"
  • ✓ السائق يضغط "تم التوصيل" → الطلب يتحول إلى "مكتمل"

📱 اختبار بعد التطبيق:

  1. عيّن سائق لطلب جديد
  2. تحقق أن الطلب مازال في حالته الأصلية (pending/processing)
  3. دع السائق يضغط "بدء الرحلة"
  4. الآن فقط يجب أن يتحول إلى "في الطريق"

💡 ملاحظة: إذا مازالت المشكلة موجودة بعد تطبيق الكود، أرسل لي نتيجة الاستعلام الأول (الفحص) وسأساعدك فوراً!
